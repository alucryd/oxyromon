# Files

- [CLI Entrypoint and the Subcommand Contract](cli-entrypoint-and-subcommands.md) - How src/main.rs registers clap subcommands, runs global startup (dotenv, OXYROMON_LOG_LEVEL logger bridged to the progress UI, data directory, SQLite pool, ROM/tmp settings), dispatches inside one scoped pooled connection, and hands long-lived servers the pool before optimize_database. Also documents the `info` dependency/statistics report.
- [Data Model, SQLite Usage and Migrations](data-model-and-migrations.md) - The systems/games/roms/romfiles/patches/headers/rules/settings schema behind oxyromon.db, how src/model.rs row types and int-encoded enums map onto it, the standalone-query and transaction conventions in src/database.rs, and the migrations/ plus cargo sqlx prepare offline workflow.
- [Feature Flags and Build Topology](feature-flags-and-build-topology.md) - How the mcp, server, use-rustls and use-native-tls cargo features gate modules, the SQLite pool shape and the served transports; how the root workspace plus crates/* (chd-rs and friends as path dependencies with their CLIs behind a `cli` feature), build.rs, Trunk, rust-embed and SKIP_TRUNK compose the CLI, the seven format CLIs, the embedded web UI and the Tauri desktop artifact.
- [System Architecture Overview](overview.md) - The layered shape of oxyromon — a clap entrypoint, one module per subcommand, shared database/model/common/config/util/transcode layers, format modules running every codec in-process over the crates/* format crates, and SQLite — plus how the GraphQL and MCP surfaces enter at the subcommand layer, and why oxyromon no longer needs any external tool.
- [Settings and Configuration Model](settings-and-configuration.md) - The settings key/value table and its category constants in src/config.rs (BOOLEANS, choice_options, choice_list_options with the chd.rs codec enums, integer_range with CHD_HUNK_SIZE_RANGE, LISTS, PATHS, NULLABLES, SORTED_LISTS), the per-system override with global fallback read path, the config subcommand surface, and the GraphQL/MCP surfaces that reuse the same validators. CHD tuning is consumed in-process by the chd-rs crate through src/chd.rs, so no tool-path or tool-version setting exists.
